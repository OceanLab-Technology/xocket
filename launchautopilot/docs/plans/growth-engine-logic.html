Growth Engine Logic

Four scoreboards and the rules that move each one: our domain rating, our AI visibility, and the same two for every product we list. Plus the Reddit pipeline that posts from makers’ own connected accounts without getting them banned.

Pick a scoreboard. Every section shows the flow, the exact logic we’d code, and what we refuse to do.

Our domain rating

Ahrefs DR is a log-scaled score driven by how many unique domains link to us with followed links, weighted by their own DR and by how few other sites each of them links to. So the job is simple to state: collect many real referring domains, and a few strong ones.

Why not copy ScrollLaunch’s DR 71 trick? They only give free makers a followed link while the badge stays up. That’s a link exchange, which Google’s link-scheme policy names. It works fast and then it’s one policy update away from being discounted. We keep the badge, drop the condition. Growth is slower, the asset lasts.

Targets (plans, not predictions)

  • Month 1–2: 30–60 referring domains from our own launches and first badges.
  • Month 3–6: badge embeds from ~25% of launched makers, first Index citations.
  • Month 6+: Index and proof-report links carry DR upward; track referring domains weekly, not DR.

The levers, in order of evidence

  1. Get into the pages engines already cite. For “Product Hunt alternatives”, that’s a handful of listicles and Reddit threads. Pitch the listicle authors with data, not money.
  2. Be mentioned, not just linked. Brand mentions correlate about 3× more with AI Overview visibility than backlinks. The Index makes us quotable.
  3. Profiles on sources engines trust: G2, Capterra, AlternativeTo, Product Hunt, Crunchbase, LinkedIn page.
  4. Our own founder account on Reddit and X, answering launch questions with disclosure. Perplexity leans heavily on Reddit.
  5. YouTube walkthroughs of the audit and Index. Cited by Perplexity and AI Overviews.
  6. Pages that answer the prompt directly, with statistics, quotes and sources (the GEO paper’s +28–41% effects), updated when data changes.
  7. Crawlable everywhere: Google, Bing via IndexNow (feeds ChatGPT and Copilot), Brave (Claude). llms.txt and MCP for agents, as hygiene.

What we report publicly: our mention rate per engine with its interval, month over month. If it doesn’t move, we say so. That page is itself marketing.

Listed products: Google and DR

One rule decides every outbound link, and it’s enforced in the database: payment makes a link sponsored; editorial approval makes it followed.

function relFor(link):
  if link.paid_order_id:            return "sponsored"   // ads, featured, newsletter slots
  if link.source == "comment":      return "ugc"         // user comments, reviews
  if link.listing.review == "approved"
     and link.listing.facts_verified: return ""             // followed: editor vouched for it
  return "nofollow"                                    // pending, rejected, unverified

This beats both competitors for free makers: they get a followed link with no badge condition. It stays safe because the link follows review, and review can’t be bought.

What else moves their Google results

  • A brand-search page. Their page on us is built to rank for “[brand] reviews”, “[brand] pricing” and “[brand] alternatives”, with verified facts and real reviews. That’s page-one real estate they control.
  • Category pages that only publish once there’s real data, so the pages they appear on are the kind that keep ranking.
  • Profiles package: 10–20 profiles chosen from citation data. Many of those links are nofollow, so we sell it for visibility and trust, not DR.
  • On-site fixes from the audit: indexing, server-rendered facts, freshness, statistics and sources.

We never promise a DR number. Competitors’ only case studies are DR jumps on sites they own or one client.

Listed products: the AI Visibility Score

One number makers can track, built from mention rates, never from a single “rank”.

// per engine e, over a period
mention_rate[e] = answers_mentioning_product / answers_sampled

// weights = rough share of buyer usage, editable per customer
w = { chatgpt: .45, google_aio: .25, perplexity: .12, gemini: .10, claude: .08 }

score    = round(100 × Σ w[e] × mention_rate[e])        // 0–100
score_lo = round(100 × Σ w[e] × ci[e].low)
score_hi = round(100 × Σ w[e] × ci[e].high)

Reddit autopilot, ban-safe

Makers connect their own Reddit account with Reddit’s official OAuth. We find threads, draft in their voice, check each subreddit’s rules, and schedule. They approve every post and comment with one tap, then we publish it through the API at the right time.

No tool can promise zero bans, because moderators decide. What we can promise is that we never do the things that get accounts banned for manipulation, and that we stop an account at the first warning sign.

The guardrails, as code

function canPublish(account, sub, draft):
  rules = cachedRules(sub)                      // /r/{sub}/about/rules + wiki, refreshed daily
  require draft.approved_by_owner                // human tap, every single item
  require draft.disclosure if mentions(product)   // "I built X" inserted, can't be removed
  require rules.allowsSelfPromo(draft.day) or not mentions(product)
  require rules.flair_ok(draft) and rules.link_ok(draft)
  require account.age_days   >= rules.min_age_estimate
  require account.karma      >= rules.min_karma_estimate
  require posts_today(account)          < 2
  require comments_today(account)       < 10
  require days_since_post(account, sub)  >= 7
  require promo_ratio(account, 30d)     <= 0.10   // ≥ 9 of 10 contributions aren't about the product
  require similarity(draft, recent_posts(account)) < 0.6  // no copy-paste across subs
  require platform_users_in_thread(draft.thread) == 0   // one of our makers per thread, ever
  require account.health >= 70
  return ok

function health(account):                        // 0–100, recomputed after every action
  100 − 25·removals_30d − 15·mod_warnings_30d − 10·negative_score_items_30d
      − 40·(visible_logged_out == false)       // possible shadowban: stop, don't dodge

We do

  • Official Reddit API with the maker’s own OAuth token
  • One account per maker: theirs
  • Approval on every item; scheduling after approval
  • Mandatory disclosure when the product is mentioned
  • Mostly non-promotional help: answer questions, share lessons
  • Unique text per subreddit
  • Pause on any removal, warning or visibility drop, and show the maker why

We never

  • Buy, warm, rent or pool accounts
  • Rotate IPs or fingerprints, or evade bans or shadowbans
  • Vote, ask for votes, or coordinate makers in the same thread
  • Post without the owner’s approval
  • Hide that the poster built the product
  • Post in subreddits that ban self-promotion

Check before building: Reddit’s Data API terms treat commercial use separately and Reddit has tightened who can register API apps. We need Reddit’s written approval for a commercial app that posts on users’ behalf before launch. The thresholds above (2 posts a day, 7-day subreddit cooldown, 10% promo ratio) are our conservative defaults, not Reddit’s published numbers, and should be tuned from real removal data.

This is the honest version of what MediaFast sells for $1,999/month. Our pitch: we help you show up in the threads buyers read, as yourself, and we’ll stop you before a moderator has to.
